# KONO launch checklist

Ready to verify:

- [ ] Complete a task, reopen it, reload, and inspect progress for every plan.
- [ ] Create/edit a note and exam; switch plans while editing. No record should move to another plan.
- [ ] Simultaneously edit different records on two devices; then edit the same field and confirm an explicit conflict.
- [ ] Lose a save response, reconnect, and confirm no duplicate credits or false reset conflicts.
- [ ] Sign into B in another tab while A is open; A's requests must be rejected.
- [ ] Delete cloud study data, reopen an old offline tab, and confirm no resurrection.
- [ ] Export, inspect import counts, restore, and download an older revision.
- [ ] Simulate unavailable browser storage; keep the unsaved draft visible and exportable.
- [ ] Test all phases/stages, including rapid phase changes, one failed PNG, retry and leaving the map while it is offscreen.
- [ ] Test keyboard search, Sanctuary actions, relaxed fishing, motion preferences, one music stream and mobile layouts.

Release decisions:

- [ ] Sign-in method confirmed.
- [ ] Launch audience and public/private access approved.
- [ ] Real-device and production identity/database checks recorded.
- [ ] Support contact, privacy/retention wording and asset licensing approved.
- [ ] Figma/Trello connections explicitly approved if wanted.

Each external tracker card should include reproduction steps, expected result, owner, test evidence and date. Suggested lists: Launch blockers, Ready to build, In progress, Ready for QA, Verified. Do not mark a card Verified based only on implementation.
